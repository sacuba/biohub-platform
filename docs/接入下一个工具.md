# 接入下一个工具

默认一个工具一个会话、一个独立 Git 仓库，与 `platform`、`contracts`、`yinglan` 平级。不创建 worktree 或新生产目录。

## 1. 会话与目录

新建如 `/opt/sci_image/sequence-tool`，先编写 `AGENTS.md`、README、依赖锁文件。指定独立开发端口（例如 3202）、数据目录 `dev-runtime/sequence-tool` 和构建目录。沿用工作区生产保护、禁止付费调用和禁止直接访问其他服务数据库的规则。测试账号只在平台创建。

每次新会话的任务说明至少含：允许编辑的仓库、任务验收条件、开发端口及数据目录、公共契约版本，以及禁止发布生产。先读规则和 Git 状态，保留已存在修改。跨项目接口变更需明确改动列表，不能凭历史聊天推断协议。

## 2. 清单与协议

参照 `yinglan/integration/tool-manifest.json`，填写唯一工具 ID、入口、能力、健康检查与任务路径，用 `contracts/schemas/tool-manifest.schema.json` 校验。清单供审核使用，不自动安装或注册工具。

公共 API 的唯一来源是契约。新增能力先改 `contracts/openapi/platform-v1.json`、样例、版本与兼容记录；运行 `npm test`。TypeScript 客户端用 `npm run generate` 生成；当前生成器的 TypeScript 应用列表为 `platform` 与 `yinglan`，Python 目标为 `sanger/app/generated`，接入时加入新工具路径。每个应用提交 `src/generated/platform.ts` 和 `contracts.lock.json`，运行 `npm run check` 确认一致。Python 客户端已经由同一 OpenAPI 生成，不能另造一套字段。

## 3. 平台注册

本版受控注册位于：

- `src/catalog.ts`：工具名称、分类、状态和已审核入口。
- `src/oidc.ts`：独立用户客户端、worker 客户端、精确回调与作用域，身份校验所用工具 ID。
- `src/api.ts`：任务聚合目标、工具权限枚举及 wallet:finish 所属工具限制。
- `src/generated`：契约生成代码，不手工编辑。
- `scripts/runtime.mjs`：仅开发环境的随机服务凭据、地址及隔离数据配置。

目前这些代码明确注册 Yinglan 与 sanger；新增工具必须更新受控分支和公共契约中的工具角色类型。不要只加一张可点击卡片就宣布接入完成，也不要放宽成接受任意 client_id 或工具上报的 user_id。

## 4. 身份与钱包

采用成熟 OIDC 客户端，授权码 + PKCE + state + nonce；严格验证发行方、受众、签名、有效期与精确回调。工具独立 Cookie；账号映射键是发行方 + subject，邮箱不能自动合并用户。每次敏感请求确认当前授权，全平台退出、停用、取消工具权限必须生效。

任务先写本地意图，再用用户令牌请求报价与冻结。用户令牌只保存在工具服务端并加密，不发给浏览器；worker 身份只能结算和释放本工具的冻结。积分和金额只能为整数。

冻结请求结果不明确时查原 task_id / 幂等键，不直接执行；冻结确认后才运行。结果写本地后持久化 settle_pending，重试结算不能重跑任务；取消或失败持久化 release_pending，由后台重试。计算状态与钱包状态分开。不要在 SQLite 事务中等待网络，不按简单超时释放仍在执行的任务。参考 Yinglan 的 `platform-wallet.ts` 和对应故障恢复测试。

## 5. 任务与验收

`GET /api/v1/tool/tasks` 只给有 task:read 作用域的平台服务，按平台 subject 过滤，校验分页。返回标准状态（取消为 cancelled）、时间、积分、钱包状态和工具结果链接；不传提示词、原始序列、图片、令牌或供应商配置。结果与文件页面再次验证当前用户归属。

验收：统一登录和全平台退出、普通用户/管理员权限隔离、任务及文件越权、报价/冻结用户绑定、服务凭据作用域、并发余额、重复请求、失败取消释放、平台中断和工具重启恢复。再做桌面、手机、键盘操作和错误/空状态检查，运行契约检查、lint、类型检查、构建和实际浏览器联调。保留结果，明确真实供应商未验证范围。

接入完成只更新开发状态；生产部署和真实用户迁移另外申请并执行，不修改已有生产工具。

## 已接入 AbTrace（sanger）

当前开发目录增加 `sanger`（Python + 原生网页）与端口 3202，私有数据在 `dev-runtime/sanger`。该工具做 Sanger 抗体质控、V(D)J/FR-CDR 注释和参考比对；不是通用基因注释。已增加明确 OIDC 用户/worker 客户端、角色枚举、钱包 annotation 能力和多工具任务聚合。工具地址和 client_id 仍显式注册，不允许远程自注册。新账号默认工具 user，既有账号需后台明确授予 sanger 权限；不会自动把平台管理员变成工具管理员。

contracts 现在同时生成 TypeScript 与 Python 客户端。平台任务摘要 cursor 为不透明的分工具分页状态，调用方只回传 next_cursor；单页合计不超过 limit，故障工具列在 unavailable。不能把 user_id 或工具地址从浏览器透传到汇总服务。

开发期 annotation 独立定价 0，单位为一个样本的一次 analysis run。工具拒绝非零报价，正式收费需再确认与验证。`npx tsx scripts/sanger-integration.ts` 验证身份、权限和业务，`sanger-recovery.ts` 验证中断、取消及恢复，后者会停止/重启 3200/3202 开发进程并使用邮件捕获。启动说明见 `../sanger/integration/README.md`。
