# BioHub 与 Yinglan 生产迁移

当前用户已明确授权上线并整体迁入旧 Yinglan 用户。平台：`https://biohub.zhangwuji.work:49998` → `http://192.168.6.111:3002`，工具：`https://image.zhangwuji.work:49998` → `http://192.168.6.111:3001`。反代、证书由用户管理，必须转发真实 Host 和 `X-Forwarded-Proto: https`；禁止缓存 `/api`、`/oidc`、`/interaction` 和升级页面。不修改开发端口 3200/3201 的配置。

## 数据与部署

`platform-prod/source` 为发布源码检出，`.env` 为独立随机密钥，`data` 为平台 SQLite、签名密钥。`yinglan-prod` 保留原路径，供应商密钥与图片仍由工具保存。平台用自定义 Node/Express 服务挂载 Next 与 oidc-provider，工具用 Next standalone；两个服务独立 Docker 容器，SQLite 在各自持久化目录，不用 PostgreSQL/Redis。

生产不能使用开发账号、数据库、测试凭据、模拟供应商或开发启动器。本轮生产平台全新初始化但暂停注册，通过整体迁移导入真实用户。平台密码保留旧 bcrypt 哈希，不要求真实用户重复注册或重置密码；旧会话失效，需重新登录。工具旧用户按原 ID 显式关联到平台 subject，不按邮箱隐式合并，因此原作品/模板/留言归属保持。

## 迁移内容

工具的 `scripts/export-platform-migration.ts export FILE` 负责导出自身账号、钱包、兑换码、规则、邮件配置；平台 `scripts/import-yinglan.ts FILE` 只读取专用迁移导出，不直接打开工具数据库。输出含敏感配置，限制 0600，仅存 `migration-runtime`，不提交代码。平台重新加密 SMTP 密码。

积分按原桶的剩余金额与有效期迁移，包括永久购买积分和有期限赠送；完整原始流水及兑换时间、批次备注等额外字段存 `migration_records` 保留审计。注册赠送 reference 规范为 `registration`，每日 reference 保留，防止重复发放。历史已兑换/作废码状态保留。迁移禁止目标库已有用户、未知归属、正在运行任务及尚未支持的有效订阅，重复导入同一导出幂等，不同导出不可覆盖。

导入完成后工具 `link ISSUER` 用原 ID 绑定平台、撤销旧密码与会话，清除本地邮箱服务器及钱包写入数据；平台为钱包唯一权威，工具保留业务数据。历史任务成功扣费和取消状态继续映射至任务中心。

## 切换流程

1. 做在线快照演练、逐用户余额和计数核对、供应商真实生成/编辑验证、权限及迁移单测。完成 Docker 构建。
2. 创建独立生产平台，暂以 `.maintenance` 显示升级页面，健康检查与 OIDC 发现接口可检查。确认公网上 HTTPS 和证书正常、issuer 精确匹配。此时旧 Yinglan 继续服务。
3. 在工作区执行 `python3 platform/deploy/cutover.py --check`。通过后执行 `--execute`。脚本获取旧生产操作锁，先冻结写入并等待任务完成，再停工具，由独立 nginx 容器在原 3001 显示 HTTP 503 升级页面，带 no-store、Retry-After。
4. 平台和工具停写后做联合备份与 SHA-256，建立候选数据副本，导出、导入、关联、逐用户余额核对，原目录留存。切换配置和容器，保留维护状态。
5. 用临时探针账户验证公网 HTTPS、secure Cookie、PKCE/OIDC、模板、返回平台及全平台退出，核对所有旧账户 ID、密码哈希、积分和兑换码数量。探针账户、会话及工具映射自动清理，未向真实用户发送消息，也不使用真实用户密码。
6. 检查成功后移除维护标志开放平台和工具。切换内失败自动恢复旧镜像、配置和原数据；不会让失败的候选库覆盖备份。

维护探针仅在 `.maintenance` 和受限 `.migration-probe` 同时存在时通过随机请求头临时开放测试请求，验收完成立即删除。不是公开登录后门。

## 备份与回滚

迁移备份留在 `migration-runtime/cutover-*/before-cutover.tgz`，含两个数据目录与环境配置，权限 0600。成功开放后，禁止只回退工具镜像或旧本地钱包；否则会产生两本钱包与新消费丢失。需维护并停止两端，保存当前状态、对比新增用户/积分/任务后再联合恢复；不可直接用迁移前快照抹掉上线后的真实交易。

正式启用 `deploy/biohub-backup.timer` 替代旧 Yinglan 单独备份定时任务，每日联合冻结写入、排空任务和钱包操作、停两容器后打包数据库/文件/密钥，自动恢复服务。联合包在 `/opt/biohub-backups`，同时保存哈希。本轮不自动删除旧备份；保留策略与异机备份可后续设置。恢复演练必须在独立路径，严禁直接覆盖生产。

## 代码存档

用户选择平台与契约先保留本地仓库，GitHub 私有仓库稍后配置。Yinglan 使用既有私有仓库。发布记录应记下三仓库提交号、两个镜像、迁移核对报告及备份路径。平台/契约远程备份未完成时必须如实说明。
