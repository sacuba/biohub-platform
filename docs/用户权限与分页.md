## 页面与权限

用户列表保留邮箱、验证状态、可用/冻结积分、平台角色、账号启停和积分调整。工具授权只显示摘要，点击「管理工具权限」打开该用户的独立弹窗。打开时重新读取用户权限和受控工具清单，保存仅提交完整 `tool_roles`，不提交或隐式更改平台角色。成功立即更新摘要；失败保留编辑内容，显示服务端错误并可再次保存。

受控工具及允许角色在 `src/catalog.ts` 与目录共用注册信息，通过管理员接口 `/api/v1/admin/tool-permissions` 返回。已接入 Yinglan、Sanger 支持 user/admin，未接入占位工具不可授权；页面不维护固定工具列表。后续接入还必须完成 OIDC、服务身份、任务与钱包边界注册。创建账号的既有默认授权、平台管理员不自动继承工具权限的语义保持原样。

弹窗使用原生模态 dialog，提供读取中、无权限、空工具清单、保存中与错误状态；保存过程中禁止关闭及重复提交。Tab/Shift+Tab 在弹窗内循环，Escape 与取消会检查未保存修改，关闭后恢复入口焦点；存在未保存修改时浏览器离页提醒。手机弹窗在可视高度内滚动，工具选择器上下排列。列表表格在手机局部横向滚动，页面不整体溢出。

## 服务端分页与兼容

`GET /api/v1/admin/users?page=1&page_size=20` 使用 SQLite COUNT 和 LIMIT/OFFSET，返回 total、page、page_size、total_pages；默认 20 条，可选 20/50/100。固定 rowid 升序，查询和余额计算只处理当前页。搜索/筛选/页大小改变回第一页，账号状态变化或数据删除导致越界时自动回到有效末页。空结果为第 1/1 页。

支持 `keyword`、`status=all|active|inactive|unverified`、`role=all|user|admin`，参数用绑定查询且严格校验。当前模型没有独立用户名，因此关键词按邮箱（含 @ 前账号名称）字面量匹配，不区分大小写，不把 `%` 或 `_` 当通配符。

列表通过请求序号及 effect 清理丢弃旧结果，搜索切换或离开管理标签后旧响应不会覆盖新列表。错误与空结果分别展示并支持重试。分页保证固定数据集的稳定顺序，跨请求不提供数据库快照；多管理员同时新增或删除用户时，总数与页内容以每次查询时的数据为准。

契约已先扩展至 0.1.1，保留不带 page 的旧 cursor/limit 调用及 next_cursor 字段；新增单用户读取和工具权限目录。按 contracts 生成器更新 platform、yinglan、sanger 的客户端及锁定摘要，工具业务代码未更改。来源、CSRF、管理员身份、最后一位管理员保护、工具 ID 和允许角色继续由服务端校验，未放宽授权边界。
